# Интернет-магазин «Web-Larёk»
«Web-Larёk» — это интернет-магазин с товарами для веб-разработчиков, где пользователи могут просматривать товары, добавлять их в корзину и оформлять заказы. Сайт предоставляет удобный интерфейс с модальными окнами для просмотра деталей товаров, управления корзиной и выбора способа оплаты, обеспечивая полный цикл покупки с отправкой заказов на сервер.

## Архитектура приложения

Код приложения разделен на слои согласно парадигме MVP (Model-View-Presenter), которая обеспечивает четкое разделение ответственности между классами слоев Model и View. Каждый слой несет свой смысл и ответственность:

Model - слой данных, отвечает за хранение и изменение данных.
View - слой представления, отвечает за отображение данных на странице.
Presenter - презентер содержит основную логику приложения и  отвечает за связь представления и данных.

Взаимодействие между классами обеспечивается использованием событийно-ориентированного подхода. Модели и Представления генерируют события при изменении данных или взаимодействии пользователя с приложением, а Презентер обрабатывает эти события используя методы как Моделей, так и Представлений.

### Базовый код

#### Класс Component
Является базовым классом для всех компонентов интерфейса.
Класс является дженериком и принимает в переменной `T` тип данных, которые могут быть переданы в метод `render` для отображения.

Конструктор:
`constructor(container: HTMLElement)` - принимает ссылку на DOM элемент за отображение, которого он отвечает.

Поля класса:
`container: HTMLElement` - поле для хранения корневого DOM элемента компонента.

Методы класса:
`render(data?: Partial<T>): HTMLElement` - Главный метод класса. Он принимает данные, которые необходимо отобразить в интерфейсе, записывает эти данные в поля класса и возвращает ссылку на DOM-элемент. Предполагается, что в классах, которые будут наследоваться от `Component` будут реализованы сеттеры для полей с данными, которые будут вызываться в момент вызова `render` и записывать данные в необходимые DOM элементы.
`setImage(element: HTMLImageElement, src: string, alt?: string): void` - утилитарный метод для модификации DOM-элементов `<img>`


#### Класс Api
Содержит в себе базовую логику отправки запросов.

Конструктор:
`constructor(baseUrl: string, options: RequestInit = {})` - В конструктор передается базовый адрес сервера и опциональный объект с заголовками запросов.

Поля класса:
`baseUrl: string` - базовый адрес сервера
`options: RequestInit` - объект с заголовками, которые будут использованы для запросов.

Методы:
`get(uri: string): Promise<object>` - выполняет GET запрос на переданный в параметрах ендпоинт и возвращает промис с объектом, которым ответил сервер
`post(uri: string, data: object, method: ApiPostMethods = 'POST'): Promise<object>` - принимает объект с данными, которые будут переданы в JSON в теле запроса, и отправляет эти данные на ендпоинт переданный как параметр при вызове метода. По умолчанию выполняется `POST` запрос, но метод запроса может быть переопределен заданием третьего параметра при вызове.
`handleResponse(response: Response): Promise<object>` - защищенный метод проверяющий ответ сервера на корректность и возвращающий объект с данными полученный от сервера или отклоненный промис, в случае некорректных данных.

#### Класс EventEmitter
Брокер событий реализует паттерн "Наблюдатель", позволяющий отправлять события и подписываться на события, происходящие в системе. Класс используется для связи слоя данных и представления.

Конструктор класса не принимает параметров.

Поля класса:
`_events: Map<string | RegExp, Set<Function>>)` -  хранит коллекцию подписок на события. Ключи коллекции - названия событий или регулярное выражение, значения - коллекция функций обработчиков, которые будут вызваны при срабатывании события.

Методы класса:
`on<T extends object>(event: EventName, callback: (data: T) => void): void` - подписка на событие, принимает название события и функцию обработчик.
`emit<T extends object>(event: string, data?: T): void` - инициализация события. При вызове события в метод передается название события и объект с данными, который будет использован как аргумент для вызова обработчика.
`trigger<T extends object>(event: string, context?: Partial<T>): (data: T) => void` - возвращает функцию, при вызове которой инициализируется требуемое в параметрах событие с передачей в него данных из второго параметра.

### Типы данных

`TPayment = "card" | "cash"` - допустимые способы оплаты в интерфейсе приложения: `"card"` — онлайн-оплата, `"cash"` — при получении.

`TBuyerErrors = Partial<Record<keyof IBuyer, string>>` - тип для объекта ошибок валидации данных покупателя. Ключи соответствуют полям интерфейса `IBuyer`, значения — тексты ошибок. Отсутствие ключа означает, что поле прошло валидацию.

#### Интерфейс IProduct
Описывает структуру товара, получаемого с сервера и отображаемого в каталоге.

`id: string` - уникальный идентификатор товара
`description: string` - описание товара
`image: string` - имя файла изображения
`title: string` - название товара
`category: string` - категория товара
`price: number | null` - цена в синапсах; `null` означает, что товар бесценен и не может быть куплен

#### Интерфейс IBuyer
Описывает данные покупателя, вводимые при оформлении заказа.

`payment: TPayment | null` - выбранный способ оплаты; `null` — способ ещё не выбран
`email: string` - электронная почта
`phone: string` - номер телефона
`address: string` - адрес доставки

#### Интерфейс IProductListResponse
Описывает объект, возвращаемый сервером на запрос GET `/product/`.

`total: number` - общее количество товаров на сервере
`items: IProduct[]` - массив товаров

#### Интерфейс IOrderRequest
Описывает тело запроса POST `/order`. Расширяет `IBuyer`, добавляя данные о составе и сумме заказа.

`total: number` - итоговая сумма заказа
`items: string[]` - массив идентификаторов выбранных товаров

#### Интерфейс IOrderResponse
Описывает объект подтверждения заказа, возвращаемый сервером на запрос POST `/order`.

`id: string` - идентификатор созданного заказа
`total: number` - сумма, списанная с покупателя

### Модели данных

#### Класс ProductCatalog
Отвечает за хранение списка товаров каталога и товара, выбранного для подробного просмотра.

Конструктор класса не принимает параметров.

Поля класса:
`items: IProduct[]` - массив всех товаров каталога
`preview: IProduct | null` - товар, открытый для подробного просмотра; `null` — ни один товар не выбран

Методы класса:
`setItems(items: IProduct[]): void` - принимает массив товаров и сохраняет его в поле `items`
`getItems(): IProduct[]` - возвращает массив всех товаров каталога
`getItem(id: string): IProduct | undefined` - возвращает товар по его идентификатору или `undefined`, если товар не найден
`setPreview(item: IProduct): void` - принимает товар и сохраняет его в поле `preview` для подробного отображения
`getPreview(): IProduct | null` - возвращает товар, выбранный для подробного отображения

#### Класс Basket
Отвечает за хранение товаров, которые пользователь добавил в корзину для покупки.

Конструктор класса не принимает параметров.

Поля класса:
`items: IProduct[]` - массив товаров, добавленных в корзину

Методы класса:
`getItems(): IProduct[]` - возвращает массив товаров, находящихся в корзине
`addItem(item: IProduct): void` - принимает товар и добавляет его в конец массива `items`
`removeItem(item: IProduct): void` - принимает товар и удаляет его из массива `items` по совпадению `id`
`clear(): void` - очищает корзину, сбрасывая массив `items` в пустой
`getTotalPrice(): number` - возвращает суммарную стоимость всех товаров в корзине; товары с `price: null` не учитываются
`getCount(): number` - возвращает количество товаров в корзине
`hasItem(id: string): boolean` - принимает идентификатор товара и возвращает `true`, если товар есть в корзине, иначе `false`

#### Класс BuyerData
Отвечает за хранение и валидацию данных покупателя, вводимых при оформлении заказа.

Конструктор класса не принимает параметров.

Поля класса:
`payment: TPayment | null` - выбранный способ оплаты; изначально `null`
`address: string` - адрес доставки; изначально пустая строка
`phone: string` - номер телефона; изначально пустая строка
`email: string` - электронная почта; изначально пустая строка

Методы класса:
`setField(field: keyof IBuyer, value: string): void` - принимает название поля и значение, сохраняет значение в соответствующее поле класса, не затрагивая остальные поля
`getData(): IBuyer` - возвращает объект со всеми данными покупателя
`clear(): void` - сбрасывает все поля в исходные значения
`validate(): TBuyerErrors` - проверяет заполненность всех полей и возвращает объект ошибок; поле считается валидным, если оно не пустое и не равно `null`; если все поля валидны, возвращается пустой объект

### Слой коммуникации

#### Класс WebLarekApi
Отвечает за взаимодействие приложения с сервером Web-Ларёк. Использует композицию: принимает объект, реализующий интерфейс `IApi`, и делегирует ему выполнение HTTP-запросов.

Конструктор:
`constructor(api: IApi)` - принимает объект, реализующий интерфейс `IApi`, через который будут выполняться все запросы к серверу.

Поля класса:
`api: IApi` - объект для выполнения HTTP-запросов

Методы класса:
`getProducts(): Promise<IProductListResponse>` - выполняет GET-запрос на эндпоинт `/product/` и возвращает промис с объектом, содержащим массив товаров и их общее количество
`createOrder(order: IOrderRequest): Promise<IOrderResponse>` - принимает объект с данными заказа и выполняет POST-запрос на эндпоинт `/order`, возвращает промис с объектом подтверждения заказа

### Слой представления (View)

Все классы представления наследуются от абстрактного класса `Component<T>` и отвечают за отображение данных в DOM. Компоненты не хранят бизнес-логику — в ответ на действия пользователя они генерируют события через `IEvents`, которые обрабатывает Презентер.

#### Класс Modal
Отвечает за отображение и управление модальным окном. Не может быть родителем других классов — всё содержимое модального окна передаётся как самостоятельные компоненты через сеттер `content`. Закрывается по клику на крестик или по клику вне окна.

Конструктор:
`constructor(container: HTMLElement, events: IEvents)` — принимает DOM-элемент модального окна и брокер событий.

Поля класса:
`closeButton: HTMLButtonElement` — кнопка закрытия модального окна
`contentElement: HTMLElement` — контейнер для содержимого модального окна

Методы класса:
`open(): void` — открывает модальное окно, добавляет класс `modal_active`, генерирует событие `modal:open`
`close(): void` — закрывает модальное окно, очищает содержимое, генерирует событие `modal:close`
`render(data: { content: HTMLElement }): HTMLElement` — устанавливает содержимое и открывает модальное окно

Сеттеры:
`set content(value: HTMLElement)` — заменяет содержимое модального окна

#### Класс Success
Отвечает за отображение экрана успешного оформления заказа (шаблон `#success`). При клике на кнопку генерирует событие `success:close`.

Конструктор:
`constructor(container: HTMLElement, events: IEvents)` — принимает DOM-элемент и брокер событий.

Поля класса:
`descriptionElement: HTMLElement` — элемент с текстом о списанной сумме
`closeButton: HTMLButtonElement` — кнопка «За новыми покупками!»

Сеттеры:
`set total(value: number)` — устанавливает текст с суммой списанных синапсов

### События приложения

В таблице ниже перечислены все события, которые генерируются в приложении, их источник и описание передаваемых данных.

#### События, генерируемые компонентами представления

`modal:open` — генерируется классом `Modal` при открытии модального окна. Данные не передаются.

`modal:close` — генерируется классом `Modal` при закрытии модального окна. Данные не передаются.

`basket:open` — генерируется классом `Header` при клике пользователя на иконку корзины. Данные не передаются.

`basket:order` — генерируется классом `BasketView` при клике на кнопку «Оформить». Данные не передаются.

`order:change` — генерируется классом `OrderForm` при изменении любого поля формы первого шага. Данные: `{ field: string, value: string }`.

`order:submit` — генерируется классом `OrderForm` при отправке формы первого шага. Данные не передаются.

`contacts:change` — генерируется классом `ContactsForm` при изменении любого поля формы второго шага. Данные: `{ field: string, value: string }`.

`contacts:submit` — генерируется классом `ContactsForm` при отправке формы второго шага. Данные не передаются.

`success:close` — генерируется классом `Success` при клике на кнопку «За новыми покупками!». Данные не передаются.

#### События, генерируемые через коллбеки (в Презентере)

`card:select` — генерируется в коллбеке, переданном в `CardCatalog`. Вызывается при клике пользователя на карточку в галерее. Данные: объект `IProduct`.

`basket:add` — генерируется в коллбеке, переданном в `CardPreview`. Вызывается при клике на кнопку «В корзину». Данные: объект `IProduct`.

`basket:remove` — генерируется в коллбеке, переданном в `CardBasket`. Вызывается при клике на кнопку удаления товара из корзины. Данные: объект `IProduct`.

#### События, генерируемые моделями данных

`catalog:changed` — генерируется классом `ProductCatalog` в методе `setItems`. Данные: `{ items: IProduct[] }`.

`preview:changed` — генерируется классом `ProductCatalog` в методе `setPreview`. Данные: `{ item: IProduct }`.

`basket:changed` — генерируется классом `Basket` в методах `addItem`, `removeItem` и `clear`. Данные: `{ items: IProduct[] }`.

`buyer:changed` — генерируется классом `BuyerData` в методах `setField` и `clear`. Данные: объект `IBuyer` с текущим состоянием полей покупателя.

### Презентер

Презентер реализован в виде набора обработчиков событий в основном скрипте приложения `main.ts` — без вынесения в отдельный класс. Такой подход оправдан тем, что приложение содержит одну страницу и один поток взаимодействия.

Презентер не генерирует события и не хранит данные. Его задача — подписаться на события моделей и представлений, запросить нужные данные из моделей и передать их в компоненты для отображения.

**Подписки на события моделей:**

`catalog:changed` — получает список товаров из `ProductCatalog`, для каждого создаёт экземпляр `CardCatalog` с коллбеком, который вызывает `catalog.setPreview()`, и передаёт отрисованные карточки в `Gallery`.

`preview:changed` — получает выбранный товар, создаёт `CardPreview` с коллбеком добавления/удаления из корзины и открывает модальное окно.

`basket:changed` — обновляет счётчик в `Header` и перерисовывает список товаров в `BasketView`.

`buyer:changed` — вызывает `buyer.validate()`, обновляет состояние кнопки отправки и текст ошибок в `OrderForm` и `ContactsForm`.

**Подписки на события представлений:**

`basket:open` — открывает модальное окно с `BasketView`.

`basket:order` — открывает модальное окно с `OrderForm`.

`order:change` — сохраняет изменённое поле в `BuyerData` через `setField()`.

`order:submit` — открывает модальное окно с `ContactsForm`.

`contacts:change` — сохраняет изменённое поле в `BuyerData` через `setField()`.

`contacts:submit` — собирает данные из `BuyerData` и `Basket`, отправляет заказ через `WebLarekApi`. При успехе очищает корзину и данные покупателя, открывает экран `Success`.

`success:close` — закрывает модальное окно.

`modal:open` / `modal:close` — добавляет или убирает класс `page__wrapper_locked` для блокировки скролла страницы.
